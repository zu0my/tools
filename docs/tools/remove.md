# 文件与文件夹删除

状态：实现中。参数解析已通过 25 个单元测试；实际删除尚未实现，程序入口尚未连接解析器。以下调用仍是设计示例，不能视为可用命令。续接步骤见 [开发进度](../PROGRESS.md)。

## 目标与范围

在 Windows 上通过命令行永久删除指定的文件和文件夹。不经过回收站，执行前不弹确认。

第一版支持明确路径、多个目标、递归删除和删除预览。不支持工具自行展开通配符，不提供 --force。

## 调用形式

~~~text
tools remove [选项] <路径>...
~~~

示例中的 tools 暂用现有包名，正式程序名仍待确定。选项必须在路径之前，解析规则遵循 [CLI 约定](../CLI.md)。

| 选项 | 含义 |
| --- | --- |
| --recursive、-r | 允许删除非空文件夹，对本次所有目录目标生效 |
| --dry-run | 预览删除范围，不修改文件系统 |
| --help | 显示帮助并成功退出，不执行删除 |

至少提供一个路径；没有路径且未请求帮助时属于参数错误。相对路径以调用者当前工作目录为准，包含空格的路径需要引号。

## 使用示例

| 调用 | 预期行为 |
| --- | --- |
| tools remove a.txt | 永久删除文件 |
| tools remove empty-dir | 删除空文件夹 |
| tools remove -r logs | 递归删除文件夹及其内容 |
| tools remove -r a.txt logs | 删除文件和文件夹，递归选项对所有目录目标生效 |
| tools remove -r --dry-run logs | 预览递归删除范围，不执行删除 |
| tools remove "D:\My Files\a.txt" | 删除包含空格路径的文件 |
| tools remove -- -notes.txt | 删除以连字符开头的文件 |
| tools remove -r -- -logs | 递归删除以连字符开头的文件夹 |
| tools remove --help | 显示帮助 |

遇到第一个路径后，后续内容全部视为路径。例如 tools remove logs -r 表示删除 logs 和名为 -r 的两个目标，并没有启用递归。此时即使 logs 删除失败，仍会继续尝试删除名为 -r 的目标。

## 删除与失败语义

- 文件和空文件夹可直接删除；非空文件夹需要 --recursive 或 -r。
- 按输入顺序分别处理目标。一个目标失败后继续处理后续目标，不撤销已经完成的删除。
- 目标不存在、权限不足或文件被占用导致删除失败时，报告目标与具体原因。
- 不强制清除只读属性，不自动提升权限。
- 目录链接只删除链接本身，不遍历其指向的目录；递归过程中也遵循此边界。
- 递归删除可能在中途失败，部分内容可能已经删除。错误信息不得暗示整个目录保持原状，也不提供回滚或自动恢复。
- --dry-run 不修改文件系统，但仍需识别目标和验证删除范围；预览阶段发现错误时按执行失败报告。预览成功不保证稍后实际删除成功。

## 输出与退出码

成功结果写入 stdout，错误写入 stderr。输出包含目标路径；失败时包含具体原因。示例：

~~~text
已删除：a.txt
已删除：empty-dir
删除失败：b.txt：拒绝访问
~~~

预览输出需明确表示尚未执行，不能显示“已删除”。预览的逐项展示格式和递归删除的输出粒度在实现设计阶段确定。

退出码沿用 [CLI 约定](../CLI.md)：全部成功为 0，存在执行失败为 1，参数错误为 2。参数错误应在任何删除开始之前报告。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 删除已有普通文件或空文件夹 | 目标被删除，退出 0 |
| 删除非空文件夹，未提供 -r | 该目标删除失败，内容不因本次操作被删除，退出 1 |
| 使用 -r 删除非空文件夹 | 删除目录及其内容，全部成功时退出 0 |
| 使用 --dry-run | 不修改文件系统，显示预览；全部预览成功时退出 0 |
| 无路径、未知选项或不合法用法 | 选项解析阶段报告参数错误，不执行删除，退出 2 |
| 目标不存在或系统拒绝删除 | 报告目标和原因，退出 1 |
| 多个目标中有失败 | 继续处理其他目标，最终退出 1 |
| 路径含中文或空格 | 按实际路径处理 |
| 使用 -- 指定以 - 开头的路径 | 作为路径处理 |
| 第一个路径后出现 -r 或 --dry-run | 作为路径处理，不改变选项 |
| 删除目录链接，或递归遇到目录链接 | 只删除链接，不删除其指向目录的内容 |

## 下一步设计与学习重点

参数解析采用标准库手写解析器，输入为 &[OsString]，输出 Command；RemoveOptions 保存 paths、recursive、dry_run，并派生 Default。UnknownCommand、UnknownOption 保留原始 OsString。

当前从普通文件删除开始，remove_path 接收 &Path，返回 std::io::Result<()>，计划直接保留 std::fs 操作错误。tempfile 已作为开发依赖用于临时目录测试。目录递归、预览执行、Windows 链接识别和最终执行结果模型尚未实现；后续按实际需求设计，不提前生成完整实现。

学习重点包括命令行输入与路径类型、Result 错误传播、文件系统交互，以及用临时文件验证副作用。
