# CLI 约定

本文定义 CLI 的共同设计基线。remove 的参数解析和帮助意图已实现；程序入口仍只输出 Hello, world!，实际执行、帮助文本、输出和退出码尚未接入。--version 尚未实现。具体验证状态见 [开发进度](PROGRESS.md)。

## 命令组织

计划采用一个命令入口，通过子命令提供不同工具：

~~~text
<程序名> <子命令> [选项] <位置参数>...
~~~

“<程序名>”是占位符，正式命令名待定。每个工具应有明确职责，子命令名称和参数在实现前写入对应工具文档。

- 无参数时显示顶层帮助，成功退出。
- 顶层和各子命令支持 --help；顶层支持 --version。
- 未知子命令、未知选项、缺失必填参数或不合法的参数值，给出具体提示并按参数错误退出。
- 参数名称优先使用易理解的英文长选项，仅在明显常用且无冲突时增加短选项。
- 选项放在位置参数之前；遇到第一个位置参数后，后续内容都按位置参数处理，不再解析选项。
- 第一个位置参数之前的 -- 表示结束选项解析，后续内容全部作为位置参数，适用于以 - 开头的路径。
- 未知选项的错误检查仅发生在选项解析阶段；进入位置参数阶段后，以 - 开头的内容也按位置参数处理。

## 输出与退出码

| 场景 | 输出位置 | 退出码 |
| --- | --- | --- |
| 成功执行、帮助或版本 | stdout | 0 |
| 执行失败，例如权限不足或资源不可用 | stderr | 1 |
| 命令用法或参数错误 | stderr | 2 |

工具逻辑返回数据，由 CLI 层负责格式化。成功结果写入 stdout；错误与诊断信息写入 stderr，避免污染管道中的结果。不默认输出调试信息。

空结果、部分成功、资源未找到是否属于失败，必须由对应工具文档明确规定。确有额外退出码需求时，先记录契约，再实现。

当前先面向人类阅读；JSON 输出、颜色、进度提示和交互输入按实际需要增加，不视为所有工具的必备功能。

## Windows 行为

- 接收包含空格和中文的路径；涉及路径的工具应验证这些场景。
- 默认以调用者当前工作目录解释相对路径，工具有例外时明确说明。
- 不默认要求管理员权限；操作需要额外权限时，说明失败对象与原因。
- 是否覆盖、跟随目录链接、处理锁定文件或长路径，由实际涉及这些场景的工具定义。
- 避免把用户输入拼成 shell 命令；需要调用外部程序时明确参数传递方式和错误处理。

## 修改类操作

涉及重命名、覆盖、删除或修改系统状态时，工具设计必须说明影响范围、冲突处理、中途失败后的状态与恢复方式。根据实际风险决定是否提供预览或确认；不机械地给所有命令增加交互步骤。

## 每个工具必须补充

在 [工具目录](tools/README.md) 中登记，并通过 [设计模板](tools/TEMPLATE.md) 明确输入、输出、例子、边界、失败语义和验收标准。共同规则引用本文，工具文档只补充具体行为和例外。
